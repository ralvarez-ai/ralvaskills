rsk mcp · for Claude Code and OpenCode

Your agent asks.You approve.rsk installs.

rsk gives your coding agent three tools. Two only read: your project’s files and a catalogue of 58 skills. The one that writes, install_skills, makes Claude Code ask you on every call.

Install rskThe three tools

3 after call 3

It lands in two files you commit.

install_skills writes the skills into .rsk/rsk.mod and their exact versions into .rsk/rsk.lock. Whoever clones the repo runs rsk install and gets the same three, at the same versions. Think go.mod and go.sum, for your agent’s skills.

From internal/mcp/tools.go

Three tools. One writes, and it is marked to say so.

The descriptions are the ones the agent reads. destructiveHint is only advice to the client; the requiresUserInteraction flag is what makes Claude Code prompt you even in auto-approve modes.

  • project_profile

    Detect this project's stack from its files and propose the ralvaskills skills that apply. Call it before scaffolding or a non-trivial change.

    readOnlyHint: true
destructiveHint: false
idempotentHint: true

  • search_skills

    Search the ralvaskills catalog by keyword. Use it to find a skill by name or intent when project_profile does not name one.

    readOnlyHint: true
destructiveHint: false
idempotentHint: true

  • install_skills

    Install one or more skills or bundles into this project by name, resolving them through the ralvaskills catalog. Writes symlinks and the project manifest. The client asks the user to approve.

    readOnlyHint: false
destructiveHint: true
_meta: anthropic/
  requiresUserInteraction

  • rsk://catalog

    A resource, not a tool: every skill with its latest version, descriptions cut to 200 characters. Name rsk-catalog.

    mimeType:
  application/json

The whole surface

Thirteen commands, grouped the way rsk --help groups them.

  • Machine setup

    init
    Set up rsk for this machine.

  • Project lifecycle

    new
    Initialize an rsk project in the current directory.
    destroy
    Remove the rsk project from the current directory.

  • Install / uninstall / update

    install
    Install bundles or skills.
    uninstall
    Remove installed bundles or skills.
    update
    Pull the latest skills and re-link.

  • Project pinning

    pin
    Pin a skill so it is imported into each tool's project config.

  • Tool configuration

    tools
    Manage tool permissions (allow/deny/list/remove).

  • Read-only views

    catalog
    Browse the catalog of available skills and bundles.
    list
    Show installed skills (project / --global).
    status
    Show installed skills and version drift.

  • Other

    mcp
    Run the MCP server over stdio.
    completion
    Generate the autocompletion script for the specified shell.

Data on stdout, logs on stderr, --output json on the read-only views, NO_COLOR honoured.

The trade-off

One binary and one config file for every project. One dependency in exchange.

What you get

  • One binary and one machine config, ~/.config/rsk/config.json, for every project.
  • Versions in a lock you commit. A clone runs rsk install and matches.
  • Claude Code and OpenCode from one install: skills are linked once into .claude/skills/.

What you accept

  • The registry at skills.ralvarez.dev has to be reachable when you install or update, or you point rsk at a local clone of the repository.
  • The MCP server needs rsk on PATH on every machine that opens the project.
  • The catalogue is one author’s standards. To change one, fork the repo and use your clone.

Quick start

Set it up once. Then let the agent ask.

rsk new registers the MCP server for both clients. Skip the last two lines if you want the agent to propose them.

# or a binary from Releases
go install go.ralva.dev/ralvaskills/v3/cmd/rsk@latest
# once per machine
rsk init
# in a project: writes .rsk/ and registers rsk mcp
rsk new
# a bundle or a skill
rsk install go-grpc
# load it in every session
rsk pin go-architect

Questions

Before you install.

Do I need the MCP server?

No. Every step works from the CLI: rsk install, rsk pin, rsk catalog. The server is there so the agent can propose skills from your files instead of you naming them.

Which clients does it support?

Claude Code and OpenCode. rsk new --for claude-code|opencode|all picks which config files rsk writes; installed skills are linked once into .claude/skills/.

Can I install a skill for every project?

Yes: rsk install <name> --global links it into ~/.claude/skills/ and ~/.config/opencode/skills/. The global bundle is meant for that.

Can I define my own bundles?

Write ~/.config/rsk/catalog.toml. A bundle with the same name replaces the built-in one; new names are added.

What are personal skills?

9 of the 58 are marked personal in the registry index. rsk catalog hides them unless you pass --include personal.

How do updates work?

rsk status shows installed skills and version drift; rsk update [name] pulls the latest and re-links. Each skill is versioned and released on its own.

What does it cost?

Nothing. rsk and the catalogue are GPL-3.0, on GitHub.
