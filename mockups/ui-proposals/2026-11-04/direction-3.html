rsk mcp · for Claude Code and OpenCode

Your agent asks.You approve.rsk installs.

rsk gives your coding agent three tools. Two only read: your project’s files and a catalogue of 58 skills. The one that writes, install_skills, makes Claude Code ask you on every call.

Install rskThe three tools

From internal/mcp/tools.go

Three tools. One writes, and it is marked to say so.

The descriptions are the ones the agent reads. destructiveHint is only advice to the client; the requiresUserInteraction flag is what makes Claude Code prompt you even in auto-approve modes.

  • project_profile

    Detect this project's stack from its files and propose the ralvaskills skills that apply. Call it before scaffolding or a non-trivial change.

    readOnlyHint: true
destructiveHint: false
idempotentHint: true

  • search_skills

    Search the ralvaskills catalog by keyword. Use it to find a skill by name or intent when project_profile does not name one.

    readOnlyHint: true
destructiveHint: false
idempotentHint: true

  • install_skills

    Install one or more skills or bundles into this project by name, resolving them through the ralvaskills catalog. Writes symlinks and the project manifest. The client asks the user to approve.

    readOnlyHint: false
destructiveHint: true
_meta: anthropic/
  requiresUserInteraction

  • rsk://catalog

    A resource, not a tool: every skill with its latest version, descriptions cut to 200 characters. Name rsk-catalog.

    mimeType:
  application/json

What the agent is told

rsk new writes the rule into CLAUDE.md.

“Never install without asking.”

@AGENTS.md
@.rsk/CLAUDE.md

<!-- rsk-mcp:start -->
## Project standards

Before scaffolding or a non-trivial change, call the rsk MCP `project_profile` tool to learn which skills apply here. Installed skills appear automatically in your skill list — invoke them with the Skill tool. Never install without asking.
<!-- rsk-mcp:end -->

real From a real rsk new run. It also registers the server in .mcp.json and opencode.json; rsk destroy removes both and the note.

The trade-off

The trade-off

One binary, one config file, every project. In exchange, the registry has to be reachable when you install, or you point rsk at a local clone.

  • rsk must be on PATH on every machine that opens the project; the client launches rsk mcp per session and stops it after.
  • The agent only proposes from files it can see. A stack with no marker file gets no proposal; ask it to use search_skills.
  • The catalogue is one author’s standards. Fork it and point rsk at your clone to change one.

Quick start

Set it up once. Then let the agent ask.

rsk new registers the MCP server for both clients. Skip the last two lines if you want the agent to propose them.

# or a binary from Releases
go install github.com/ralvarezdev/ralvaskills/v3/cmd/rsk@latest
# once per machine
rsk init
# in a project: writes .rsk/ and registers rsk mcp
rsk new
# a bundle or a skill
rsk install go-grpc
# load it in every session
rsk pin go-architect
