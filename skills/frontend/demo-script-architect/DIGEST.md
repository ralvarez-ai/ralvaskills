# demo-script-architect (digest)

Presenter-centric demo scripts: narrative flow, visual cues, progressive reveals, query-to-explanation alignment, redundancy audits.

## Always-on rules
- Narrative over feature lists. Story arc: observe → understand → apply → verify. Bridge narration gives the *why*.
- Name elements with purpose, e.g. `YI-100 (pump status indicator)`.
- Map each reference to a visible on-screen element.
- Explanations match the query: name the mechanism (parallelization, routing, lookup).
- Progress basic → complex → combined → edge cases. Stack elements only for a new insight.
- Conversational: contractions, direct address ("Watch", "Notice", "Observe"), short sentences.
- Commentary interprets significance, not mechanics; sets up the next question. Bridge narration connects each demo to the next with a *why*.
- Each demo has six parts: Demo Setup, Visual Cue, Action/Query, Processing (2–3 sentences), Expected Responses (per system state), Commentary.

## Hard constraints
- Never point to something the audience can't see on screen.
- Don't claim a mechanism the query does not show (e.g. context-learning when tags are explicit).
- No redundancy: don't repeat the same query/capability in consecutive demos.

Invoke the full skill when: creating a live demo, a structured walkthrough, or turning a spec into a narrative; or when you need the progression table, anti-pattern examples or the review checklist.
