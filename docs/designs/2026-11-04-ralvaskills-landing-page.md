Rebuild: `cd mockups/ui-proposals/2026-11-04/_tools && python3 build.py`. The generator reads
`registry/index.json`, `skills/`, `internal/config/catalog.toml`, `cmd/rsk/setup.go`,
`internal/mcp/tools.go`, `internal/mcp/resource.go`, `.rsk/rsk.mod`/`.lock` and the latest
`v*` git tag at build time, and **asserts** the anchors (58 skills, 15 bundles, 12 `AddCommand` +
cobra `completion` = 13, the three tool names, one mutating tool, `rsk://catalog`). If the tree
drifts, the build fails instead of the page lying. Harness setup: `npm install` in `_tools/`
(Playwright 1.64 + axe-core 4.10; `node_modules/` is git-ignored). It uses the Chromium already in
`~/.cache/ms-playwright` (override with `CHROME=`).

### Concept per direction

All three share one family layer (`family.py`): the Ralvarez brand kit for the page, the header,
kicker, buttons, film engine, reveals, scroll kit, copy button, footer with the real block wordmark,
and a source list ("Where every number on this page comes from"). Terminal surfaces keep rsk's
termkit TokyoNight theme. They differ in mechanism:

- **A — the manifest as the argument.** *"`go.mod`, but for your agent’s skills."* A dark terminal
  runs `rsk new` → `rsk install go-grpc` → `rsk pin go-architect`, and a real-format
  `.rsk/rsk.mod` assembles itself with a diff gutter while `rsk.lock` resolves beneath it. Then: the
  six files `rsk new` really writes, this repo's own `rsk.mod` (night band), the 13 commands grouped
  as `rsk --help` groups them, the trade-off, quick start. Personality: exact, editorial.
- **B — the catalogue as a real number.** A giant **58** over a unit chart: one square per skill,
  grouped by `skills/<domain>/`, the 9 personal ones dashed. The count is the spine: 58 → 15 bundles
  (a live filter that behaves like `rsk catalog`, personal hidden unless `--include personal`) →
  139 releases (weekly histogram from `published_at`) → 13 commands + 3 tools → "the trade-off, in
  ones". Personality: loud, numeric.
- **C — the agent loop.** *"Your agent asks. You approve. rsk installs."* Swimlanes You · Agent ·
  rsk mcp with the three calls as they really are: `project_profile` (read-only, a real response),
  the approval (the one human step, in the warning colour, in the You lane), `install_skills`
  (writes). On phones the lanes reflow into a numbered thread. Then: the tools with their real
  annotations, the 13 detection rules, the real `CLAUDE.md` rule *"Never install without asking."*,
  the trade-off, quick start. Personality: protocol, calm.

### Recommendation: C, and why it beats A and B

**C wins** because it is the only device that shows what nobody else does. A's "go.mod for skills"
is the clearest sentence on any of the pages, but it would describe any package manager for prompts.
B's 58 proves scale, but a count says nothing about why rsk differs. C shows the two things that
are particular to rsk, and both come from the code: the agent proposes skills from file evidence
(`signals.go`, with the proof file in the payload), and the only write is a human decision forced on
every call (`requiresUserInteraction` in `tools.go`, plus the `CLAUDE.md` rule `rsk new` writes).
That is also the trade-off made visible: the agent proposes, you approve. Five-second test: the h1
says what happens and who decides; the lede says the clients (Claude Code, OpenCode) and the
catalogue size; the lanes show the mechanism.

C's weakness is that it assumes the reader knows what an MCP tool is, and says little to someone
who just wants the CLI. The combined page fixes that with A and B.

### The combined page (`direction-4-combined.html`)

One story, one sample project, end to end:

1. **The loop** (C's hero film): profile → you approve → install, for `go-architect`,
   `docker-architect`, `cli-tool-architect`.
2. **What it writes** (A's device, second film): the same three skills landing in `rsk.mod` and
   `rsk.lock`, framed as "after call 3". The ◆ line in the terminal stands for the agent's call.
3. **What `rsk new` writes** (A): the real six-file tree and the real `CLAUDE.md`.
4. **Catalogue** (B): **58** as the heading, the bundle filter with a live count, personal hidden.
5. **Tools** and **Detection** (C): annotations and the 13 signal rules, with the full real JSON.
6. **The real file** (A, night band): this repository's own `rsk.mod` and lock.
7. **Commands** (A), **trade-off** (weighted give/take), **quick start** (copy button), **FAQ** (7
   questions, each answer traced to a file).

Pacing alternates paper / tinted / paper / night; a family section rail (01–11, left edge,
≥1400 px) tracks position and grows the active tick. 89.9 KB, two films, both with Pause/Replay.

### Round 2 — family theme and scroll effects (2026-11-04)

The first pass themed the whole page with rsk's termkit TokyoNight palette. The owner asked for the
sharper family look used by the ralvagym, finance, identity and notifier landing pages, and for
motion tied to scrolling. Both changed in `family.py`; the page copy and the seven flags did not.
The system was read from `mockups/claude-design/2026-11-04/landing-page.html` in each sibling repo
(their tokens, 4/6 px radii, mono kickers, 2 px rules, square-plus-dot mark and rail); nothing in
those repos was edited. Borrowed specifically: ralvagym's drifting giant number and family mark,
finance's view-timeline entry, identity's count-up idea, and notifier's progress bar inside the
film control.

**Theme.** Page chrome now uses the Ralvarez brand kit those four pages share: ink `#0c0e11` /
paper `#f4f5f7`, cyan accent `#2bbbd6` (dark) and `#00758c` (light), the 4/6 px radii, mono
uppercase kickers, 2 px rules and the square-plus-dot family mark. Terminal surfaces are scoped with
`.tn` and keep termkit TokyoNight (`#16161e`, `#c0caf5`, `#7aa2f7`), so the product inside the frame
still looks like the product. Contrast of every page token against every page background, and of the
terminal tokens against the terminal surfaces, is asserted at build.

**Motion.** One scroll kit is shared by all four pages:

| Effect | Where | Reduced motion / JS off |
|---|---|---|
| 2 px reading-progress bar under the sticky header | all | bar hidden without JS |
| Header hairline once scrolled, active section in the nav | all | static header |
| Family rail ticks, active tick grows, labels on hover/focus | ≥1400 px | rail hidden below 1400 |
| Staggered one-shot reveals + `k-rule` wipe | section copy | content visible |
| h1 line masks (lines rise out of a clipped box) | C and combined | content visible |
| Count-ups on the section numbers | B, combined | plain HTML number |
| Histogram bars rise in sequence | B releases | bars at full height |
| Scroll-linked sideways drift on the 58 | B hero | number static |
| Sticky “after call 3” copy beside the device | combined | static |
| Progress bar inside Pause/Replay | both films | control hidden without JS |

Everything except the progress bar and the sticky header sits under `html.anim`, which the head
script adds only when `prefers-reduced-motion` does not match. Count-ups read their final value from
the HTML and end there; nothing scroll-jacks, and no content depends on an animation to become
readable. Scroll-linked drift uses `animation-timeline: view()` behind `@supports`, so browsers
without it get the static composition.

### Round 3 — the package, and the build that could ship (2026-11-04)

Two gaps were left open by round 2: the family tokens were a hand copy (the Risks note below counted
"five places"), and the proposals had no deployable output.

**The palette now comes from the package.** `_tools/tokens_extract.py` reads
`tokens.css` + `sharp.css` from an installed `@ralvarez-ts/tokens`, resolves the effective value of
each role per theme, and writes `_tools/tokens.json` with the package name, version and the SHA-256
of both source files. `family.py` loads that snapshot instead of its own dicts, and
`python3 tokens_extract.py <pkg> --check` fails when the package moves. Roles the package does not
own are layered in `family.py`: the TokyoNight terminal, `info` (no status role for it), the ink
label on a cyan fill, and the device shadow. Radii stay at the base ladder (4/6 px, `--radius-control`
and `--radius-card` from `tokens.css`), not sharp's zero geometry: every sibling landing page draws
4/2/3 px, and a fully square console reads as an app, not a page. Both ladders are recorded in
`tokens.json` as `radii` and `radii_sharp`.

**One value changed, and it was a real bug.** The hand-copied `--line-2`, used on every button and
control boundary, was 1.51:1 on paper and 1.88:1 on ink. The package's `--color-border-strong` is
the role built for WCAG 1.4.11 and measures 3.75:1 and 3.05:1. `_check()` now asserts that 3:1 floor,
so the page cannot regress to a decorative border. Status tones also became the package's
(`#135c36`/`#6b4d08`/`#9d2a24` light, `#4cc789`/`#e0b04a`/`#ff8a83` dark) and the tinted bands use
`--color-surface` instead of a white card. Everything else was already identical, which is what makes
the swap checkable rather than a redesign.

**The build can now produce a site.** A first `site.py` emitted the static page plus Cloudflare's
`_headers` and `robots.txt`; Round 4 replaced it with the Vite build in `web/` and the script was
removed rather than kept as a second deploy path.

**Hosting, recommended and not yet applied.** Two hosts, each with one job:

| Artifact | Host | Why |
|---|---|---|
| `index.json` at `https://skills.ralvarez.dev` | GitHub Pages, unchanged | `internal/config/fs.go` hardcodes it as `DefaultRegistryURL`; moving it breaks every installed `rsk`. The publish workflow uploads `registry/` as the site root today. |
| The landing page | Cloudflare Pages, `rsk.ralvarez.dev` | Same account and Direct Upload flow as `ralvarez.dev`; `_headers`, branch previews and instant rollback, which GitHub Pages does not offer. Publishing the page stops riding the skill-publish workflow. |

Doing it on the existing Pages project instead (`skills.ralvarez.dev/`) needs no new secrets, but the
artifact must then always contain both files: one workflow, and every copy change re-uploads the
registry. That coupling is the reason for the split, not the DNS.

### Round 4 — the page becomes a web project (`web/`, 2026-11-04)

The proposals proved the design; this makes it shippable as software. `web/` is React 19 +
TypeScript strict + Vite 8 + pnpm 11, one prerendered document. The Python generator is gone from
the deploy path: it stays only as the proposals' harness in `mockups/`.

- **Data.** `web/scripts/gen-data.mjs` (Node, `smol-toml`) reads `registry/index.json`,
  `skills/**`, `internal/config/catalog.toml`, `cmd/rsk/setup.go`, `internal/mcp/{tools,resource}.go`,
  `.rsk/rsk.mod`/`.lock` and the git tag, and **fails** on drift from 58 / 15 / 12 / 3. It runs from
  `predev` and `prebuild`. Constants that cannot be derived (the real `rsk new` run, the real
  `project_profile` response, `rsk --help` groups, the quick start, the source list) live in
  `src/data/facts.ts`, typed and labelled on the page. One generator, one language, no Python in
  the web build.
- **Tokens, for real this time.** `src/styles/tokens.css` imports `@ralvarez-ts/tokens`
  (`tokens.css` + `sharp.css`), and `base.css` aliases the page roles to it (`--bg: var(--color-bg)`,
  `--line-2: var(--color-border-strong)`); no hex is copied. That exposed a bug the static snapshot
  hid: the package's status roles live in an `@theme static` block, which only Tailwind compiles. In
  a plain CSS build they do not exist, so `var(--warn)` resolved to nothing and the approval card's
  "✓ Allowed" fell back to transparent (axe caught it at 1.11:1). The fix is Tailwind's Vite plugin
  and `tailwindcss/theme.css` only — no utilities, no preflight — so `@theme` becomes real `:root`
  variables.
- **Prerender.** `vite build` alone would ship an empty `#root`, losing the JS-off readability the
  proposals had. `scripts/prerender.mjs` renders the app once with `react-dom/server` into
  `dist/index.html` (40 KB of markup) and `main.tsx` hydrates it. The theme button is client-only so
  there is no hydration mismatch. Effects do not run on the server; the markup is the films' final
  state.
- **Components.** One component per section (`src/sections/`), the shared device with its own film
  (`components/Device.tsx`), chrome (`Header`, `Rail`, `Footer`, wordmark), and the motion kit as
  hooks (`useFilm`, `useReveals`, `useCounts`, `useScrollKit`, `useTheme`). The catalogue filter is
  React state instead of DOM mutation; the films still drive classes on the rendered markup so their
  end state is the HTML.
- **Gate.** `scripts/verify.mjs` serves `dist/` with `vite preview` and runs the same bar: axe at
  390/1440 × light/dark × motion/reduced, no horizontal overflow, every reveal fired, every
  count-up settled, and JavaScript off (headline, 12.8k characters of copy, no overflow).

| Check | Result |
|---|---|
| axe, 8 runs | 0 violations (after fixing a duplicate landmark name, the theme button's name mismatch and the `@theme` contrast bug) |
| Overflow, reveals, count-ups | pass |
| JS off, 390 + 1440 | pass: 29 sections, ~12.8k characters, no overflow |
| Output | HTML 40 KB prerendered, CSS 41.9 KB (9.6 KB gzip), JS 308 KB (90 KB gzip) |

Hosting is still the open item from Round 3: the artifact is now `web/dist`, so the Cloudflare
Pages step is `pnpm build` then `wrangler pages deploy dist`.

### Round 5 — names, tokens and layers (2026-11-04)

The port was faithful to the proposals, and that was the problem: a page built
from "directions" carried their names. `.k-`, `.a-`, `.b-` and `.c-` selectors
said which proposal a rule came from, not what it styles; `--bg2`, `--rk`, `--d2`
said nothing at all; and `base.css` was one 19 KB sheet for the whole page.

- **Tokens name intent.** The palette block is now `--surface-page`,
  `--surface-raised`, `--surface-sunken`, `--text-strong`, `--text-muted`,
  `--text-accent`, `--border-subtle`, `--border-control`,
  `--status-ok|warn|danger|info`, `--radius-control|panel`, `--space-1..9`,
  `--duration-1..4`, each an alias of `@ralvarez-ts/tokens` where the package has
  the role. No component hard-codes a colour or a radius.
- **Classes name roles.** `manifest-file__line`, `call__message--request`,
  `agent-hero__line`, `filter__chip`, `unit-chart` — component first, then part,
  then state. Short names that meant different things per sheet (`.p`, `.b`,
  `.d`, `.n`) were renamed per file, not globally. JavaScript-toggled states all
  start with `is-` (`is-visible`, `is-filming`, `is-pending`, `is-match`).
- **Variants are attributes.** `Button variant="primary|ghost"`,
  `Tag tone="readonly|destructive|hint|sample"`, `Section tone="paper|sunken|ink"`.
  CSS matches `[data-variant]` and `[data-tone]`, so a variant is a prop, not a
  string appended to a class.
- **Components own their chrome.** `Header`, `Rail`, `Footer`, `Manifest` in
  `components/`; the primitives in `components/ui/` (`Button`, `Tag`, `Panel`,
  `Section`, `Eyebrow`, `CopyBlock`, `FilmControl`, `BrandMark`, `Wordmark`).
  `Panel` has a `flush` mode for a table or pre that *is* the body, and every
  section now declares its band with `<Section tone>` instead of an inline
  `background` style.
- **Styles are one sheet per component.** `styles/index.css` imports
  `tokens → reset → layout → chrome → controls → panel → motion → terminal →
  tradeoff`, then one sheet per page area. The split was routed by selector, not
  by line ranges, because the generated CSS was a single concatenated line.
- **Dead rules went.** The combined page reuses parts of A, B and C, so its
  sheets still carried the standalone heroes, the release chart and the bundles
  index. Rules whose classes the prerendered page does not contain were dropped:
  85 rules and 6.6 KB of CSS.

Verification after the refactor: typecheck, build, the full gate (8 axe runs,
overflow, reveals, count-ups, JS-off) and a pixel comparison against the
pre-refactor captures. The only differing pixels are the section rail's active
tick, which depends on scroll history, and the content that the old capture
script never revealed.

### Round 6 — parity with the combined page (2026-11-04)

The port had drifted from `direction-4-combined.html` in ways the gate could not
see, so the two were compared directly: text of `main` (diff), a computed-style
walk over every element, and per-section pixel diffs at 1440.

What was actually wrong, in the order the comparison found it:

| Symptom | Cause |
|---|---|
| Page 728 px taller; an extra section | `Told` was rendered although the combined page never had it. Removed. |
| Catalogue led with **15 bundles** | Ported B's own hero heading instead of the combined page's replacement: **58 skills the agent chooses from, in 15 bundles**. |
| `writes` and `faq` full-bleed, content off-screen | `className="wrap"` survived the rename in two sections; `.wrap` no longer exists, so no container width or gutter. |
| Every 3–6 px section height off; code looked too wide | The prune dropped `code,pre,kbd,.mono{font-family:var(--font-mono)}` because `.mono` was unused; all code fell back to generic `monospace`, changing line boxes and metrics. |
| Hero line mask and arrow draw dead | `agent.css` was renamed with the C map only, so `.anim`, `.f-run`, `.f-h` and `.in` stayed in its selectors. |
| Theme toggle 11 px wider, unstyled | `.theme-toggle` and the ghost variant are client-only (hydrated after the prerender), so the prune could not see them. |
| Copy block lost the gap between note and command | The port put both spans on one line instead of the mockup's newline-separated lines. |
| `mimeType: application/json` on one line; two curly apostrophes | JSX whitespace collapsing and a typographic substitution. |
| No theme transition | The circular View Transition wipe was never ported. Now 520 ms from the button, same easing. |

After the fixes: text differs only in film state at capture; **every section
height matches exactly**; per-section pixel diffs are zero outside the reading
progress bar and the rail tick, which depend on scroll history.

> That last claim was too generous: the diff used a threshold of 24 levels, and
> the "rail tick" it excused was a whole missing component. Round 7 corrects it.

The gate grew a `WIRED` list for this reason: a selector that stops applying
leaves valid markup and valid axe results, so `verify.mjs` now asserts the mono
stack on `code`, the 0.95 s hero mask transition, the 0.16 s button transition,
the theme toggle's 12 px padding, the film control's display, the panel radius and
that the section rule has a background.

### Round 7 — parity in use, not only in stills (2026-11-04)

Round 6 compared still screenshots. Looking at the page next to the mockup again
found five differences that stills, and a loose threshold, had hidden.

| Symptom | Cause |
|---|---|
| Both films (hero, "What it writes") never played; a Replay button that did nothing | `useFilm(fig, …)` was called but `ref={fig}` was never put on the `<figure>`, so the engine found no root and returned. The page sat in its final state. |
| The pinned line collapsed to `[]` mid-film | The ref wrapped the whole line; the mockup swaps only the value. The ref now sits on `.manifest-file__pinned`. |
| No section rail at any width | `.section-rail{display:none}` in `chrome.css` loads after the `@media (min-width:1400px)` block in `layout.css`; equal specificity, so the later `none` won. The default now sits above the media rule, in the same file. |
| Header nav never marked the current section | `Header` was not given the active id. It now is, and sets `aria-current`. |
| Tools section tinted | `tone="sunken"` the mockup does not have. Invisible at a 24-level threshold (8 levels apart), 97 % of the section at a threshold of 2. |

How it was found, and what now guards it:

- `scripts/compare.mjs` captures both pages (any widths and themes, or a running
  dev server through `WEB_URL`) with a per-element style dump; `compare-film.mjs`
  samples each film at fixed times; `compare-behaviour.mjs` drives the filter,
  rail, theme toggle, count-ups, progress and copy button. Diff PNGs at a
  threshold of about 2, per section.
- `verify.mjs` fails if a film does not start on scroll, leaves steps hidden or
  untyped when it ends, loses the `pinned =` key, if the rail is not
  `display:block` and fixed at 1400 px and up (`WIRED` entries can carry a minimum
  viewport width), or if the nav and the rail do not follow the scroll. It also
  waits for running films before axe, which measures contrast and would otherwise
  catch a step mid-fade. Reduced motion must never hide anything.
- `.github/workflows/check-site.yml` runs `pnpm lint`, `pnpm build` and `verify.mjs` on pull
  requests and on `main` when `web/` (or the files `gen-data` reads) changes. The
  parity scripts stay manual: they need the mockup and a human to read the
  result.

Interactive states were compared too (`compare-states.mjs`): rest, hover, keyboard
focus and the open FAQ for buttons, the theme toggle, the film control, filter
chips, FAQ items, nav, brand and copy, in both themes. Pixels and computed styles
match in every state, and the states differ from rest, so the match is not
vacuous. The 390 dark spread was capture timing: `compare.mjs` now waits for films
and reveals, and three runs agree at 737 px (0.01 %, text anti-aliasing).

Biome now owns style in `web/` (CSS excluded). Its first pass found a real a11y
slip, `aria-label` on role-less `<pre>` elements, which assistive tech ignores; the
labels were redundant under their headings and are gone. The focusable scrollable
code blocks are one `CodeRegion` component carrying the single documented
suppression.

Result at a threshold of 2: 0.005 % of pixels differ at 1440 and about 0.01 % at
390 in light, all of it the progress bar, text anti-aliasing and the top rules
still drawing. 390 dark varies from run to run (0.05 % at worst), which is
capture timing. One deliberate difference remains: after a filter click the
mockup's re-render drops the "9" from "the 9 personal ones", and the page keeps
it.

### Round 8 — the Ember palette (2026-11-04)

The palette was reviewed and found plain: near-monochrome cool grey with one cyan
that did everything (links, buttons, big numbers, rail, arrows), so the three
actors had no colour identity; "You approve" was the weakest colour on the page, a
muddy mustard in light; and the terminal's fixed Tokyo Night blue-violet clashed
with the cyan. The sunken bands barely differed from the page, so light read flat.

Four palettes were drawn as full copies of the combined page
(`mockups/ui-proposals/2026-11-04/palette-*.html`, viewer `palette-viewer.html`,
generated by `_tools/palettes.py`, which refuses to write a palette that fails
WCAG 2.2 AA): Ember (warm paper, vermilion), Aurora (violet), Signal (ink and lime)
and Ember with a counterpoint. axe passed on all five pages in 20 combinations.

**Chosen: Ember with the counterpoint.** Warm paper and a vermilion accent step
away from the cyan-on-grey look of developer tools, and the human gets its own cool
colour: teal for the "You approve." line, the YOU lane, the request arrow and the
approval dialog, so "you approve, rsk installs" reads by colour too. The amber stays
for what writes (`--status-warn`). Aurora is the most common look in AI products;
Signal is the loudest in dark but its lime cannot carry text in light, so it would
have given two personalities depending on the visitor's theme.

How it is built:

- **One deliberate deviation from `@ralvarez-ts/tokens`**, in `tokens.css`: an Ember
  layer overrides the package's `--color-*`. It needs `html:root[data-style][...]`
  because sharp.css sets them at `:root[data-style=sharp][data-theme=...]` and an
  equal-or-lower specificity silently loses (the first attempt only changed dark).
  The JavaScript-off path (no `data-theme`) is covered in both system schemes.
- **`--human`** is a new semantic role, used by `agent.css` in place of
  `--status-warn` where the thing means "you".
- The night band and the terminal take the Ember dark palette; termkit's Tokyo Night
  is no longer used there. The wordmark and the favicon follow the accent, and the
  `theme-color` metas and the JS that updates them use the new page colours.

Checked against the proposal, not just against the old page: full-page diff at
threshold 2 is 0.005 % (dark) and 0.03 to 0.05 % (light), where the only region
above noise is the dark band in light theme, a few levels of 255 in one panel with
no gradient to explain it; 11 elements in 4 interactive states, both themes, match;
the films and behaviour match as before. The build passes lint, typecheck and the
gate (axe in eight combinations). Not validated: focus rings, forced-colors and the
tinted backgrounds beyond what axe measures; the brand change (the rsk wordmark is
no longer blue) is the owner's call.

## Components and interfaces

- **Family layer** (`family.py`): the Ralvarez brand tokens for the page and a `.tn` scope with
  termkit TokyoNight for terminal surfaces; contrast of every text token against every background
  is **asserted ≥ 4.5:1 at build**, for the light page, the dark page, the night band and `.tn`.
  `data-theme` + toggle (`aria-pressed`, stored in `localStorage['rsk-theme']`, system default,
  circular View Transition wipe when motion is allowed). A head script adds `html.anim` only when
  `prefers-reduced-motion` allows; every hide/animate rule sits under `.anim`. The scroll kit
  (progress, sticky hairline, rail, count-ups, reveal stagger, rule wipe, line masks) lives in the
  same file; count-ups restore the HTML's final text and expose `window.kCountsDone()` for tests.
- **Film engine** (`kFilm`): steps `{at, dur, fn(p)}` on a pausable timeline, `reset()` for the start
  state, `end()` cleanup; the final state **is** the plain HTML. Plays once when 30 % visible, pauses
  when the tab is hidden, Pause/Play/Replay button (hidden without JS). Typed text is driven by the
  timeline (Pause freezes it); the typed layer is `aria-hidden`, the full text sits once in `.sr`.
  Hidden steps keep their box (no layout shift).
- **Reveals**: one-shot IntersectionObserver, opacity + transform with a 70 ms `--i` stagger,
  ending at 1. Section rules use the same observer for a clip wipe; the C hero h1 lines rise under
  a mask. No scroll-linked opacity. A Chromium-only `animation-timeline: view()` layer adds the
  drifting 58 and is skipped elsewhere.
- **Catalogue filter**: chips with `aria-pressed`, a live count, an `aria-live` note; non-matching
  tags are de-emphasised with a dashed border and muted text (contrast-safe), never opacity.
- **390 px**: A puts the device between h1 and lede; B shrinks the squares; C reflows lanes into a
  numbered thread with "Agent → rsk mcp" labels; chips scroll horizontally; tables become stacks.

### Flags (found while reading the code — flagged, not fixed)

1. **README version drift** (from the brief): `README.md:136` says "Latest release `v3.3.0`"; the
   latest tag is `v3.4.1` and `bin/rsk --version` prints `rsk 3.4.1`. The pages read the version
   from the tag.
2. **Spanish on the agent surface** (from the brief, extended): the `rsk://catalog` description in
   `internal/mcp/resource.go` is Spanish ("Catálogo de skills disponibles…"), and so are three
   JSON-schema field descriptions the agent sees: `ProjectProfileIn.Path` "Ruta del proyecto; por
   defecto el cwd" and `SearchSkillsIn.Limit` "Por defecto 10, máximo 25" (`internal/mcp/tools.go`),
   `InstallSkillsIn.Scope` "project (por defecto) | global" (`internal/mcp/install_tool.go`). The
   live tool schemas in this session show the Spanish strings.
3. **`llm-app` bundle names two skills that do not exist**: `llm-app-architect` and
   `agent-architect` (`internal/config/catalog.toml:107-108`) are in neither `skills/` nor the
   registry index. On B and the combined page, picking `llm-app` shows a count of 4 and a note naming the two missing skills.
   Not tested: what `rsk install llm-app` does with the missing two.
4. **AGENTS.md vs code on MCP registration**: AGENTS.md says the server is registered in
   `.claude/settings.json` under `mcp`; the code writes `.mcp.json` (`internal/tool/mcp.go:16`) and
   `opencode.json`, as the real run confirms.
5. **`rsk init --force` help text**: "Overwrite existing rsk.mod if present" (`cmd/rsk/setup.go:56`),
   but `init` writes `~/.config/rsk/config.json`, not `rsk.mod`.
6. **`rsk new` without a terminal says yes**: with stdin closed and no `--mcp`/`--guide`, the real run
   registered the MCP server and tried to install `rsk-guide` (skipped only because the sandbox had
   no config). `cmd/rsk/new.go:203-209,259` asks through `termkit.Confirm(cmd, false, …)`; whether
   that is meant to default to yes outside a TTY is for the owner to decide. The README phrase
   "registered by `rsk new`" matches the observed behaviour.
7. **Personal skill names are public**: the 9 personal skills are
   listed in the public `registry/index.json`. The pages show their count and hide the names unless
   you press `--include personal` (mirroring the CLI). Owner call whether the public page should
   name them at all.
8. **Brand split**: rsk still has no web identity of its own. The pages therefore split in two:
   page chrome borrows the Ralvarez brand kit from the sibling landing pages (cyan `#2bbbd6` on ink
   `#0c0e11`, paper `#f4f5f7`, 4/6 px radii), while every terminal surface keeps rsk's real
   termkit TokyoNight theme (`#16161e`, `#c0caf5`, blue `#7AA2F7`). termkit's light accent
   `#2E7DE9` is 3.1:1 on paper, so the wordmark keeps the CLI's darkened gradient steps and the
   page never uses it as body text. termkit's `Brand` colour (`#9854F1`, purple) is deliberately
   unused. No font files are embedded: the pages use system sans and mono stacks, so they will look
   different on macOS and Windows than in these Fedora screenshots, and the siblings' embedded
   Inter/JetBrains Mono is not reproduced.

### Not covered

- **Screen readers** (NVDA, VoiceOver, Orca): not run. axe checks structure, not the listening
  experience of the lanes or the live count.
- **Firefox and Safari**: not run. View Transitions (theme wipe), `color-mix()` and the
  scroll-linked drift (`animation-timeline: view()`) fall back or differ; `text-wrap` is
  progressive. Firefox and Safari get the static positions and the IntersectionObserver reveals,
  not the drift.
- **Real devices**: only emulated viewports at DPR 1; no touch, no real 390 phone, no zoom/400 %
  reflow test, no Windows High Contrast run (a `forced-colors` block exists but was not seen).
- **The five-second claim**: judged by me, not tested with people.
- **Copy accuracy beyond the facts table**: phrasings such as "makes Claude Code ask you on every
  call" rest on the code comment for `requiresUserInteraction`; OpenCode's behaviour with that meta
  key was not checked.
- **`install_skills` and `rsk install` output**: not run (no installs allowed), so call 3 and the
  post-install files are sample.
- **Fonts**: system stacks only, as rendered on this Fedora machine.

## Risks

- Generated from the tree at build time: re-run `python3 build.py` after the catalogue changes or the
  numbers go stale; a broken anchor fails the build on purpose.
- The scratch-folder outputs (`rsk new`, `project_profile`) are pasted into `_tools/data.py`; they
  will not follow CLI changes until someone re-runs them.
- Hosting: `https://skills.ralvarez.dev` still serves `registry/` as the site root. The page has a
  deployable build (`site/`) but no deploy yet: the host is chosen, the project and its DNS record
  are not. Whatever happens, `index.json` must stay at its current URL — the CLI hardcodes it.
